# M14-M15 可观测性与项目收尾设计

## 目标与边界

M14 为现有 HTTP Chat、LangGraph、LLM 和业务 Tool 增加最小可观测能力；M15 整理仓库、文档和演示入口并完成最终验收。不引入 Collector、Grafana、日志平台、SLO 或新的业务能力。

## M14 设计

使用 OpenTelemetry Python SDK 手动创建 Span，并在开发环境通过 Console Span Exporter 输出。手动埋点能直接展示父子调用关系，且只需 SDK 一个直接依赖，无需额外自动插桩包。

请求进入 FastAPI 后创建根 Span，并生成或接受 `X-Request-ID`。LangGraph 的 Router、Supervisor、Specialist、Knowledge、Tool 和 HITL 节点建立子 Span；百炼文本、结构化、Tool Calling、Embedding 和 Rerank 调用建立模型 Span。

请求级 `ContextVar` 只保存当前请求真正需要的累计数据：执行路径、模型调用次数、Tool 调用次数、输入/输出 Token、估算成本和错误。响应结束时输出一条结构化摘要日志，并通过 `X-Request-ID` 与 `traceparent` 响应头关联。现有 JSON API Contract 不变。

Token Usage 直接读取 Provider 响应中的 `usage`。成本仅按 LLM 输入/输出 Token 与环境变量中的每百万 Token 单价估算；Embedding/Rerank 仍记录调用和延迟，但不虚构无法可靠换算的费用。缺少 usage 时记录零，不影响业务响应。

异常记录类型和 Span 状态，不记录 API Key、Authorization、Prompt、用户消息、Tool 参数或 Provider 原始响应。

## M15 设计

README 更新到 M15，补齐当前能力、配置、启动、登录、演示、观测与验收说明。系统架构、Multi-Agent Workflow、RAG、HITL 四张图直接使用 Mermaid，避免维护二进制制图文件。

提供一个 `scripts/demo.py` 作为最终演示入口，复用现有 API：登录后顺序演示普通对话、订单查询、商品查询、知识问答、跨 Agent 协作及退款审核提示。脚本不包含 Secret，不绕过 HTTP/API 边界，不自动执行管理员批准，以免重复运行产生危险写操作。

保留现有定向 smoke/evaluation 脚本；只删除能够确认无调用且无学习价值的临时代码。Docker Compose 继续作为一键启动方案，不增加服务。

## 测试与提交

M14 按 TDD 增加观测上下文、Token/Cost 计算、请求日志和调用路径测试，再执行 Ruff、完整 pytest、Compose 与真实请求验证，独立提交。

M15 验证 Demo 脚本的 API 行为，更新 README 和开发记录，执行最终 Ruff、pytest、Alembic、Seed、Docker 健康、真实百炼/RAG/HITL/Agent Evaluation、Secret 与 Git 工作区检查，独立提交。
