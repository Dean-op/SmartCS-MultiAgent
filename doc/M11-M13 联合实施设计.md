# M11～M13 联合实施设计

## 1. 实施目标

本次连续完成三个相互依赖的里程碑：

- M12 先建立最小 JWT 身份边界，替换 `DEVELOPMENT_USER_EMAIL`。
- M11 在真实 `current_user` 上实现退款写入、确定性规则和 LangGraph HITL。
- M13 对最终认证后的完整 Agent System 做小型真实评估。

最终不增加新 Agent，不改变 M9 RAG，不实现 OAuth、Refresh Token、复杂 RBAC、ML 风控、多级审批或通用 Evaluation Framework。

## 2. 实施与提交顺序

按依赖而非编号顺序实现：

1. `feat(auth)`：登录、JWT、current_user、角色边界、Tool 身份替换。
2. `feat(refund)`：退款命令、规则、Migration、interrupt/resume、Review API。
3. `test(evaluation)`：Agent Dataset、指标脚本和真实结果。

三个 Commit 在一次任务中连续完成。M11 已批准的详细资格、风险和 HITL 规则继续以 `M11 退款写操作与Human-in-the-loop设计.md` 为准，本文件只说明与认证、线程和评估的集成关系。

## 3. M12 身份认证

### 3.1 依赖与算法

- Password Hash：`pwdlib[argon2]`
- JWT：`PyJWT`
- Algorithm：HS256
- Token TTL：60 分钟
- Token Claims：`sub`、`exp`

JWT 只签名、不加密，不放入密码、Email 或业务数据。`sub` 保存 User UUID；每次请求重新通过 UserService 加载 User 并检查 active。

### 3.2 API

```text
POST /api/v1/auth/login
```

JSON Request：

```json
{"email": "alice@example.com", "password": "..."}
```

Response：

```json
{"access_token": "...", "token_type": "bearer", "expires_in": 3600}
```

认证失败统一返回 401，不区分 Email 不存在或密码错误。

### 3.3 current_user

```text
Authorization: Bearer JWT
→ decode HS256/exp/sub
→ UserService.get_user(UUID(sub))
→ active UserData
```

- Chat API 需要 customer 或 admin 登录。
- Review API 额外要求 `role == admin`。
- 不创建 Permission、Scope、Policy 或 RBAC Framework。

### 3.4 Seed 与配置

Seed 为以下开发账户写入 Argon2 Hash：

- `alice@example.com`：customer
- `admin@example.com`：admin

开发明文密码只用于 README/测试，不写入数据库或 Git Secret。新增配置：

```text
JWT_SECRET=
JWT_ALGORITHM=HS256
JWT_ACCESS_TOKEN_EXPIRE_MINUTES=60
```

真实 `.env` 使用本地随机 Secret，`.env.example` 只提供需要替换的开发示例值。

### 3.5 身份与 Conversation

外部 conversation_id 仍为 UUID，内部 thread_id 改为：

```text
{current_user.id}:{conversation_id}
```

同一用户可以恢复自己的 Conversation；不同用户即使提交相同 conversation_id，也会进入不同 PostgreSQL Checkpoint Thread。

ChatState 增加 `user_id`，用于 Graph 内部 Tool 执行。`user_id` 来自 current_user，不来自 LLM 或请求 Body。

## 4. M11 退款写操作

### 4.1 Tool

Refund Agent 增加：

```text
request_refund(order_number, amount?, reason)
```

LLM 只能给出订单号、用户请求金额和原因。Graph 从 `ChatState.user_id` 和内部 thread_id 提供可信上下文。

### 4.2 确定性业务规则

Eligibility：

- 订单存在且属于 current_user。
- 非 cancelled。
- 支付状态不是 unpaid/refunded。
- 30 天窗口：delivered_at 优先，否则 paid_at。
- 剩余可退金额 = order total − 非 rejected/cancelled Refund。
- amount 缺省时取剩余金额；必须大于 0 且不超过剩余金额。

Risk：

- amount ≤ ¥100。
- 用户近 30 天非 rejected/cancelled Refund 少于 2 次。
- 同时满足为 AUTO_APPROVE，否则 MANUAL_REVIEW。

### 4.3 幂等与数据模型

Alembic Migration：

- `refunds.request_key VARCHAR(64) NULL UNIQUE`
- `human_reviews.thread_id VARCHAR(80) NULL INDEX`

request_key 为 SHA-256(`internal thread_id + order_id`)。同 Thread 重放返回原 Refund，不重复写入。

### 4.4 状态转换

Auto：

```text
eligible + low risk → Refund completed + completed_at
```

Manual：

```text
eligible + review risk
→ Refund pending_review
→ HumanReview pending + internal thread_id
→ Graph interrupt
```

Approve：

```text
HumanReview approved + reviewed_at
Refund completed + completed_at
```

Reject：

```text
HumanReview rejected + reviewed_at
Refund rejected，不设置 completed_at
```

### 4.5 interrupt/resume

ChatState 只增加 `pending_review`。Human Review 节点：

1. 读取已提交的 pending_review。
2. `interrupt()` 返回 JSON-safe 审核信息。
3. Review API 使用相同 internal thread_id 调用 `Command(resume=...)`。
4. 节点恢复后调用确定性 resolve_review。

interrupt 前的 Refund/HumanReview 创建已由前一 Tool 事务完成并受 request_key 保护。interrupt 节点本身在暂停前无写副作用。

### 4.6 Review API

```text
GET  /api/v1/reviews/pending
POST /api/v1/reviews/{review_id}/approve
POST /api/v1/reviews/{review_id}/reject
```

- 全部要求 admin current_user。
- Action Body 只有可选 `note`。
- pending 返回 review/refund/amount/reason/conversation 信息。
- approve/reject 在同一次 HTTP 调用内 Resume Graph 并返回最终状态。
- 重复处理返回 409，不重复写入。

## 5. Repository、Service 与事务

新增具体查询/命令，不创建 Generic Repository 或 Unit of Work：

- OrderRepository：按 user/order `FOR UPDATE` 加载 Aggregate。
- RefundRepository：按 request_key 查询、创建 Refund、统计近期退款。
- HumanReview 查询与写操作保留在 RefundRepository/RefundService 边界内。
- RefundService：`request_refund`、`list_pending_reviews`、`get_review`、`resolve_review`。
- Repository 不 commit；BusinessTools/API 使用 `session_factory.begin()` 作为事务边界。

## 6. Graph 调整

Refund Agent 暴露两个 Tool：

- `get_current_user_refund`
- `request_refund`

Tool Isolation 允许 Refund Agent 使用这两个，其他 Specialist 仍维持原白名单。

新增 Graph 节点：

```text
human_review
```

路径：

```text
refund_agent
→ request_refund
├→ rejected/auto → refund_agent → END
└→ manual → human_review → interrupt
                          → resume → resolve → END
```

ChatService 增加 `resume_review(internal_thread_id, decision)`，普通 `respond` Contract 不变。初次 interrupt 转换为正常“等待人工审核”回答。

## 7. M13 Agent Evaluation

### 7.1 Dataset

约 20 条 JSON Case，字段按场景可选：

- `query`
- `actor_email`
- `expected_route`
- `expected_agents`
- `expected_tool`
- `expected_arguments`
- `expected_outcome`

覆盖：

- order/refund/product/knowledge/general。
- complex order+refund、order+knowledge。
- read Tool 与 request_refund。
- ownership、未登录、customer Review 禁止、admin Review 允许。
- Prompt 注入不能提供 user_id、risk、approve。
- 重复退款和超额退款。

### 7.2 指标

- Router Accuracy
- Agent Selection Accuracy
- Tool Selection Accuracy
- Tool Argument Accuracy
- Task Success Rate
- Safety/Authorization 通过率

每个指标明确分母，只对适用 Case 计算。Complex Agent Selection 比较按顺序的 Specialist 列表。

### 7.3 执行

- 自动化测试验证指标函数、安全和确定性业务规则。
- 显式真实脚本使用最终 JWT/Graph 边界执行小数据集。
- 写操作 Case 使用专用测试数据或稳定 request_key，避免污染评估重复运行。
- 输出 `evaluation/agent_results.md`，保留失败 Case，不修改标注追求高分。

M13 与 M9 Retrieval Evaluation 独立，M13 不重新计算 Retriever Hit@K。

## 8. 测试与验收

M12：

- 登录成功/失败、过期/伪造 JWT、inactive User。
- Chat 未登录 401。
- current_user ownership。
- customer 403 Review、admin 允许。
- 相同 conversation_id 跨用户 Checkpoint 隔离。

M11：

- Low Risk 自动完成。
- Manual Review interrupt。
- approve/reject resume。
- 不存在、ownership、未支付、全退、过期、超额。
- request_key/重复 Review 保护。
- PostgreSQL 真实写入与状态关系。

M13：

- 指标计算测试。
- 真实 Agent Evaluation。
- 少量真实退款/HITL Smoke。

只运行三个模块的定向测试、必要 pytest、Migration upgrade、少量真实模型调用和相关 Docker/API 验证。不重复 RAG Evaluation、全部历史 Agent Smoke、M0 基础设施或无关验收。

## 9. 限制

- 没有 Refresh Token、OAuth、密码修改、注册或复杂 RBAC。
- Review API 是单管理员角色检查，没有权限矩阵。
- completed Refund 不调用真实支付机构。
- 风控只有金额和近期次数规则。
- HITL 没有超时、提醒、多级审批或撤销。
- Agent Evaluation 数据集小，结果只代表当前 Seed 和 Prompt。
